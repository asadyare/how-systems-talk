# Lab 1: How my machine is wired

Environment: Windows 11 host, Ubuntu on WSL2.

## `ip a` – interfaces and addresses

```text

    inet 127.0.0.1/8 scope host lo
    inet 10.255.255.254/32 brd 10.255.255.254 scope global lo
    inet6 ::1/128 scope host proto kernel_lo

    inet 172.31.240.109/20 brd 172.31.255.255 scope global eth0
```

> I used `sudo` because without it `ss` hides which process owns each port.

## What it means

- **IP:** `172.31.240.109/20` on `eth0` is a private WSL address behind Windows.
- **Gateway:** `172.31.240.1` is the Windows host routing my traffic out to the internet.
- **DNS:** `10.255.255.254` is the WSL DNS proxy on loopback, which forwards queries to Windows.
- **IPv6 scope:** I have `::1` loopback and a link-local `fe80::` address. The later DNS trace showed no usable route to external IPv6 servers; that does not disable local IPv6. `ip route` above shows IPv4 routes only.
- **Listening:** only DNS (`systemd-resolved`) and time sync (`chronyd`), all on loopback.
- **WSL detail:** the `10.255.255.254:53` listener has no Linux process because WSL itself handles it.

## Security takeaway

In this snapshot, no listed socket is bound to `0.0.0.0` or the `eth0` address. That limits direct exposure, but does not prove network unreachability: Windows forwarding, firewall rules and other host services need separate checks.
